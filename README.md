# ui-testgen-prototype

Прототип компонентов фреймворка генерации UI-тестов Android на основе LLM
и динамического анализа интерфейса. Магистерский проект CSE7942 Research
Project, автор — Тельбай Арыстан (7M06101 Software Engineering).

[![CI](https://github.com/ATelbay/ui-testgen-prototype/actions/workflows/ci.yml/badge.svg)](https://github.com/ATelbay/ui-testgen-prototype/actions/workflows/ci.yml)

## Состояние

Реализован первый модуль будущего фреймворка — проверка локаторов
(Selector Validator) по дампу UIAutomator:

- `src/uitestgen/snapshot.py` — разбор XML-дампа в плоский список элементов;
- `src/uitestgen/validator.py` — проверка локатора: элемент найден
  однозначно (`found`), найдено несколько элементов (`ambiguous`) или ни одного (`absent`).
  Две реализации: `NaiveValidator` (полный обход дерева) и `IndexedValidator` (хеш-индексы);
- `src/uitestgen/workload.py` — детерминированная нагрузка для бенчмарка.

Генерация Test IR, обращения к LLM и раннеры (Compose UI Test, UIAutomator)
ещё не реализованы. Их планируется добавить в следующих версиях.

## Структура

```text
src/uitestgen/        исходный код прототипа
tests/                модульные, регрессионный и smoke-тесты (unittest)
benchmarks/           снятие дампов (adb), микробенчмарк, профилирование
data/snapshots/       8 реальных дампов экранов Settings (Android 17, эмулятор)
results/              результаты экспериментов практики 8
docs/                 план бенчмаркинга
scripts/reproduce.sh  повтор проверок и измерений
.github/workflows/    конфигурация CI (GitHub Actions)
```

## Требования

Нужен CPython 3.9 или новее. Код использует только стандартную библиотеку,
поэтому внешние пакеты не устанавливаются (см. `requirements.txt`). Для
повторного снятия дампов дополнительно нужны Android SDK Platform Tools (`adb`)
и запущенный эмулятор или устройство.

## Быстрая проверка

Команды выполняются из корня репозитория:

```bash
python3 -m venv .venv && source .venv/bin/activate
python -m unittest discover -s tests -t . -v
python benchmarks/bench_validator.py --quick --output results/local
```

Ожидается `OK` для всех тестов и файл `results/local/summary.csv` со
строками для `naive` и `indexed`. Флаг `--quick` уменьшает объём нагрузки.
Это проверка работоспособности, а не измерение.

## Воспроизведение эксперимента практики 8

Полный повтор без эмулятора использует сохранённые дампы:

```bash
scripts/reproduce.sh
```

Скрипт запускает тесты, микробенчмарк (`results/micro/`) и профилирование
(`results/profile/`). На Apple M4 Pro полный прогон занимает около 5 минут.
Состав нагрузки и результаты проверки локаторов при повторе совпадают.
Абсолютные задержки и ускорение зависят от процессора и интерпретатора
и оцениваются заново на каждом стенде.

Повторное снятие дампов и задержки `uiautomator dump` выполняется отдельно.
Эмулятор нужно остановить до микробенчмарка, как в практике 8:

```bash
emulator -avd <AVD> -no-window -no-audio -no-snapshot -read-only &
adb wait-for-device
scripts/reproduce.sh --capture   # только дампы и results/macro
adb emu kill
scripts/reproduce.sh             # тесты и микробенчмарк без эмулятора
```

Параметры, которые фиксируют воспроизводимость:

| Параметр | Значение | Где задан |
| --- | --- | --- |
| Seed генерации локаторов | 42 | `bench_validator.py --seed` |
| Масштабы дерева | 1, 2, 4, 8, 16, 32 | `--scales` |
| Локаторов на экран | 100 (40 % уникальные, 20 % составные, 20 % неоднозначные, 20 % отсутствующие) | `--queries`, `workload.SELECTOR_MIX` |
| Повторы | 3 прогрева + 20 замеров × 5 отдельных процессов | `--warmup`, `--repeats`, `--process-runs` |
| Образ эмулятора | `system-images;android-37.1;google_apis_playstore_ps16k;arm64-v8a` | `results/macro/device.json` |

Каждый запуск сохраняет конфигурацию, версию Python, ОС, процессор и commit
Git в `results/micro/run.json`. Поле `git_dirty` показывает, были ли
незафиксированные изменения в `src/` и `benchmarks/`. Скрипт не запрещает
измерения при `true`, поэтому такие результаты не следует фиксировать
в репозитории.

## Тесты и CI

| Файл | Что проверяет |
| --- | --- |
| `tests/test_snapshot.py` | разбор границ, порядок обхода, флаги, ошибки формата |
| `tests/test_validator.py` | контракт валидатора для обеих реализаций; регрессию `naive` = `indexed` на реальных дампах, включая все сочетания атрибутов каждого элемента |
| `tests/test_workload.py` | детерминированность и пропорции нагрузки, сохранение исходов при масштабировании |
| `tests/test_benchmark_smoke.py` | полный запуск бенчмарка в режиме `--quick` |

Workflow `.github/workflows/ci.yml` запускается при push в `main`,
pull request и вручную. На Python 3.9 и 3.12 он компилирует исходники,
выполняет все тесты и smoke-прогон бенчмарка, затем сохраняет его CSV
как артефакт сборки. Пороговые значения времени в CI не проверяются:
общие раннеры GitHub дают нестабильные времена. Корректность ускоренной
реализации проверяет регрессионный тест, а производительность измеряется
локально на фиксированном стенде.
