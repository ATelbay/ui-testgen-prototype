# План бенчмаркинга (практика 8)

## Исследуемая система

Подсистема получения снимка интерфейса и проверки локаторов. Она
выполняется на каждом шаге сценария и в каждой итерации исправления
локатора (repair feedback), поэтому её задержка входит во время
получения теста. Шаг состоит из стадий:

1. `uiautomator dump` на устройстве и передача XML через adb;
2. разбор XML (`parse_hierarchy`);
3. построение валидатора (для `indexed` — индексов);
4. проверка q локаторов.

## Вопросы

- Q1. Какая стадия определяет задержку шага?
- Q2. Даёт ли индексирование выигрыш по сравнению с полным обходом,
  и с какого числа локаторов на снимок оно окупается?
- Q3. Как время проверки растёт с размером иерархии?

## Нагрузка

| Нагрузка | Состав |
| --- | --- |
| Макро | 8 экранов Settings × 10 повторов `dump` + `exec-out cat` |
| Микро, реальные экраны | те же 8 дампов (40–82 элемента) |
| Микро, масштабирование | копии верхних поддеревьев, ×1…×32 (до ≈2,6 тыс. элементов) |
| Локаторы | 100 на экран, seed 42: 40 % уникальные, 20 % класс+текст, 20 % только класс, 20 % отсутствующие |

## Метрики

- задержка шага и стадий: медиана, p95, p99;
- задержка одного локатора (мкс) и ускорение indexed/naive;
- порог окупаемости: q* = (build_indexed − build_naive) / (query_naive − query_indexed);
- память: пик при разборе и объём, удерживаемый валидатором (tracemalloc);
- стабильность: коэффициент вариации медиан между 5 процессами.

## Инструменты

`time.perf_counter_ns`, `tracemalloc`, `cProfile` (аналог perf/gprof для
Python), `adb`, Android Emulator. Сборщик мусора отключается на время
замеров; перед замерами выполняется прогрев.

## Контроль корректности

Перед измерением обе реализации проверяют все локаторы на всех масштабах.
Любое расхождение прерывает запуск. Тот же инвариант закреплён тестом
`test_naive_and_indexed_agree_on_real_snapshots`.

## Ограничения

Один стенд (Apple M4 Pro, эмулятор arm64), одно приложение (Settings),
синтетическое масштабирование и смесь локаторов, заданная генератором,
а не LLM. Результаты предварительные; основная серия эксперимента
(практика 7) использует реальные приложения корпуса.
